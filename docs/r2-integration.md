# R2 integration — phase 1

Preview-only authenticated smoke test. This commit does not change the existing upload paths, database records, or public URLs.

POST /api/r2-smoke-test with Content-Type: application/json, and JSON body {"businessId":"<owned business UUID>","sessionToken":"<existing Supabase user access token>"}. The diagnostic uses a same-origin HTTPS POST body because preview proxy headers did not work. Do not enable request body capture or log tokens; this is diagnostic-only, not the planned production authentication transport. Never put credentials in URLs or logs. Vercel must expose its system environment variables VERCEL_ENV and VERCEL_GIT_COMMIT_REF; the endpoint is disabled outside the dedicated preview branch. Use a controlled test business. The only payload is a fixed small PNG. The server generates a unique key under r2-integration-test/owner/business/, uploads conditionally, retrieves and checks bytes, deletes only the object it successfully created, and confirms 404. A transport failure during PUT may leave a test object; review the test prefix before any eventual migration. No production or existing media keys are touched. No public bucket access or CORS configuration needed for this smoke test.

Run node --test tests/r2-smoke.test.cjs for mocked tests. Live smoke test requires a protected Preview deployment and an authenticated owner. Next phase: larger-media direct uploads, server authorization and content verification, publication-compatible stable URLs, cleanup integration, isolated database tests, migration inventory and rollback. Do not enable public access for private documents. Do not migrate or remove source data until separately approved.

Revision 4 includes stage-specific sanitized error reporting and a read-only Preview readiness endpoint at GET /api/r2-readiness. It reads a randomly generated test key, never returns object contents and performs no writes. Remove this diagnostic before production.
